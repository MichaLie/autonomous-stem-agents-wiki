## Findings

No admission-blocking issue was found in this sample. Two wording refinements were sent to the Foundation editor and coordinator:

1. **PlantRNA-FM (`bfm-mrna-fm-plantrna-fm`)** — the current input/output string should distinguish base embeddings from predictions after task-specific fine-tuning. The [publisher full text](https://pmc.ncbi.nlm.nih.gov/articles/PMC11652376/) (Fig. 2 and adjacent results) describes fine-tuning for genic-region annotation and translation-efficiency prediction. The [model card](https://huggingface.co/yangheng/PlantRNA-FM/raw/main/README.md) shows base-model embedding inference. Suggested wording: “Plant RNA sequence -> embeddings; task-specific predictions after fine-tuning.” This does not alter acceptance: multiple downstream tasks, direct paper-to-hub ownership, MIT model wording and ungated `model.safetensors` were confirmed. Splitting the old mixed family and keeping the historical stable ID with PlantRNA-FM satisfies the recorded condition; MIT must not be transferred to residual mRNA-FM.

2. **ScDiVa (`bfm-scdiva`, held)** — “silently” overstates the loader defect because the [inference source](https://huggingface.co/warming666/ScDiVa/raw/main/modeling_scdiva.py) prints warning/error messages. Lines 263–316 show the loader selecting `model.safetensors`, passing it to `torch.load`, catching loading exceptions, and returning the initially constructed model. Suggested wording: “may return random initialization after a warning/error message.” Label inherited paper-only wording in the audit reason as historical, because public artifacts now exist. The conservative HOLD is supported: the [repository README](https://raw.githubusercontent.com/wangmingxuan666/ScDiVa/HEAD/README.md) still describes an inference SDK awaiting internal release review, and a successful official loader/checkpoint pair was not verified. Static source inspection establishes the fallback behavior; it is not a runtime test or proof that every possible loading path fails.
